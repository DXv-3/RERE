# Persistent Agent Workspace

Agent records belong to the paired server. Avatar images are immutable content-addressed assets; stored profiles keep their SHA-256 reference. RPC reads hydrate the image for current clients. Reusing an image deduplicates its bytes, and reset clears the profile reference without deleting recoverable assets. Older inline documents remain readable and normalize on their next save/import. Browser preferences remain a recoverable compatibility copy. Migration keeps the original IndexedDB archives and a local profile/assignment backup; the server stores a payload and receipt for each import. Repeated receipts must have identical content. Re-imports preserve profile edits, pins, memory, and conversation assignments while merging message IDs. New source history (including a first recovered transcript) revokes an earlier recovery and routine-ownership attestation. Cached continuation text is not execution authority: an unaccepted retry rechecks current recovery, archive and routine ownership. Only the orchestrator can identify an already accepted command replay, which returns its existing receipt without creating work.

An imported profile with missing history is still imported work. It cannot become a ready new agent merely because its archive is absent. Imported readiness requires a handoff with evidence and no blockers. Original task and approval messages remain historical records; opening a primary conversation creates no provider turn. Primary thread and creation-command IDs are deterministic across clients, while secondary task conversations use fresh IDs. Inert preparation uses the existing Scratch folder allocator with setup explicitly disabled; opening an agent cannot run project scripts. A personal folder is bound to the primary conversation and reused thereafter.

The common orchestration dispatch boundary adds agent context and enforces recovery and routine ownership. Keep that boundary common to browser, native, MCP, and scheduler sends. The production server provides AgentWorkspace to the orchestrator. Tests without the service retain the upstream behavior; AgentDispatch.test.ts explicitly exercises the enabled boundary. Provider execution still uses existing routing and provider-switch infrastructure.

Context includes the full saved instructions, provenance, editable memory, a reviewed handoff, and recent complete archived messages. Preview and send use the same context builder; instructions consume the same budget and are not appended a second time. The default budget is 24,000 characters; omissions are visible and the full merged archive stays on the server. This is not a tokenizer-based model-window guarantee. Provider-native conversation handoff and compaction remain responsible for their own live histories.

Recovery is not hosted-session migration. Grok Bot memory, files, connected accounts, browser/computer sessions, and routine ownership require supported recovery and independent verification. Archive events never create or activate scheduled jobs. A manual ownership attestation is not a cross-service distributed lock: do not claim duplicate prevention against a still-running hosted routine without verifying the original is stopped.

Mobile uses the same contracts and environment storage. Its current agent detail surface exposes history, memory, model choices, and image editing. Source shapes, icon paths, and the historical timeline are shared across clients. Native acceptance and hosted capability inventories remain rollout work; do not claim parity from compilation alone.

Tool access (`profile.blockedToolGroups`) is a deny-list of the five MCP capability groups, stored on the profile so it syncs with the agent. The server applies it to each MCP request in `makeMcpAuthMiddleware` (`AgentToolAccess.ts`), not when a credential is issued, so a change reaches a running session on its next call. `McpSessionRegistry.resolve` must keep returning the credential's own scope: `ProviderSessionManager` compares it to decide whether to rotate. A switched-off group leaves `capabilities` and is listed in `blockedGroups`. Other Conversations is the exception to dropping the capability: a blocked agent still needs its goal tools and its own thread, so `orchestration` checks that mean "own thread only" use `holdsOrchestration`, and everything else (`readCaller` defaults to this) refuses. A tool that only touches the calling thread must opt in with `readCaller("own-thread")`. `agents.save` keeps the stored list when a client that predates the field sends the profile without it; clearing is an explicit empty list.

Secrets (`AgentSecrets.ts`) are server-local and are not on the agent document, so agent sync cannot carry them. A value lives in `ServerSecretStore` (named from a hash of the agent id plus the validated secret name) and, after `secret_file`, in a 0600 file inside a 0700 per-agent directory under the state directory. The tables hold metadata (including the sites a secret is limited to) and requests, never a value. This is not isolation between agents or from the machine: an agent that can run commands runs as the server's OS user, so it can read the store, print a secret it may use, or send it elsewhere. What the design does is keep the value out of the conversation, the database, logs, spans, queued messages and error text by default. The value is `Redacted<string>` from the wire (`AgentSecretValue` decodes straight into it, with no length check, because a failed check would quote the value) to the one caller that needs the text. `observeRpcEffect` records the method and fixed attributes only, never the payload, and every `AgentSecretError` message is fixed text per reason. Do not add an input to those attribute bags, and do not put a value in an error.

`preview_type` takes a secret by name and the server swaps the value in just before the request to the browser. If the owner limited the secret to sites, the handler first asks the browser host for the tab's current URL (the `status` operation, as the tool icon does) and refuses unless the page's origin is allowed or when it cannot be determined. That check and the typing are two requests, so a page that navigates between them can still receive the value. Every browser tool result and tool icon passes through the masking in `invoke` (`preview/handlers.ts`), which replaces the agent's secret values and their URL-encoded forms with `[secret]`. Masking is best-effort text matching: it cannot see a screenshot, an encoding it does not know, or a value split across fields. Values under 6 characters are refused at storage so that nothing stored is too short to mask, and when the agent's values cannot be read the browser call fails instead of returning unmasked content.

The value is sent to whichever client is hosting the browser for that thread (the preview-automation host the broker routes to), and any operate-scope client can host.
